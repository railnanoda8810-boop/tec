アジャイル ≠ イテレーティブ

アジャイルは価値観、イテレーティブは作り方です。両方を組み合わせられます。Agile Allianceも、イテレーティブとインクリメンタルは異なる概念と説明しています。

ウォーターフォールが向く場合もある

途中で要求が変わりにくく、先に仕様を決める必要がある仕事では、計画を重視する方法が有効です。反対に、作ってみるまで必要な機能が分からない場合は、反復的な進め方が向きやすくなります。

03 / COMBINE

初心者には「小さく作って直す」が基本

イテレーティブとインクリメンタルは組み合わせると特に使いやすくなります。

例として、録音アプリを完成させるまでの順番を見てみましょう。

  1. まず録音だけ作る（Incremental）

    録音ボタンを押すとファイルが保存される、という最小の使える状態にする。

  2. 録音が失敗する問題を直す（Iterative）

    同じ条件で比較し、改善したかを確かめる。

  3. 文字起こしを追加する（Incremental）

    新しく使える機能を1つ増やす。

  4. 認識精度を高める（Iterative）

    同じ音声で結果を比べ、修正する。

牛尾剛さんの実践ともつながる

牛尾さんは、AIに実装を任せながら、荒いものから作り、構造や外から見える動作を把握して実際に試す反復的・増分的なスタイルを説明しています。ただし「コードを全く読まなくていい」「設計不要」ということではありません。 本人の記事を読む ↗

例外：認証、データ保護、外部公開など、後から修正すると影響が大きい設計は、最初から考える必要があります。

06 / AI WORKFLOW

AIに任せるときの基本ワークフロー

AIを動かすことではなく、完成した成果物を中心に考えます。

  1. 目標を書く

    誰が、何をしたら、どういう結果になるかを1文にする。

  2. 現状を調べる

    既存のコードや資料を確認し、分かることと不明なことを分ける。

  3. 最小の作業に分ける

    利用可能な成果物を1つ決める。必要に応じて技術実験もする。

  4. AIに実装してもらう

    変更範囲、禁止事項、実際の成功条件を渡す。

  5. 実物を確かめる

    自動テストだけでなく、画面・動画・生成ファイルなども確認する。

  6. 改善か次の追加かを決める

    失敗なら原因を調べる。動くなら新しい価値を追加する。

このままAIに渡せる指示文

AI開発の基本指示
あなたは、初心者がAIと一緒にソフトウェアを開発する際の支援者です。
【目標】（実際に確認できる動作を一文で書く）

次の順番で進めてください。
1. 既存コード、制約、過去の失敗を確認する。
2. 分かっていることと、まだ不明なことを区別する。
3. まず実際に使える最小の一部分を決める。
4. 事前に成功条件（どう動けば合格か）を決める。
5. 変更する範囲を絞って実装する。
6. テストログに加え、実際の成果物を確認する。
7. 問題があれば再現条件を保存し、原因候補を1つずつ試す。
8. 次の機能追加や改善に進む前に、現時点の結果をまとめる。

重要：コード量・AI稼働時間・報告数は完成条件にしない。
取り返しのつかない操作、外部公開、データ削除などは、事前に人間の確認を求める。
最後に、専門用語を説明しながら「何が完成し、何が未検証か」を教えてください。
人間が確認すべき場面

データ削除・本番公開・権限変更・重要な品質判断など、失敗した際の影響が大きい操作。安全なテストや調査は自動化し、重要な判断に人間の確認を集中させると停滞を減らしやすくなります。

07 / CASES

実際の開発にどう使う？

既知の開発目標を例にした説明です。ここで現行コードを監査したという意味ではありません。

AutoRigの物理演算

髪・服などの揺れを自然にする仕事は、使える機能を増やすより、同じ条件で見た目を改善する反復が中心です。

Iterative仮説検証回帰テスト美術的QA

成功条件：指定した区間の映像が自然で、ほかの区間を壊していないこと。

WorkLensの録音アプリ

録音・保存・文字起こし・検索は、利用できる機能を1つずつ増やすのに向いています。

IncrementalPoCE2E

成功条件：端末上で実際に録音・保存・検索が使え、データの安全性が確保されていること。

なぜ完成までの流れが大切なのか

AIが調査・実装を大量に進めても、統合や検証ができていなければ利用可能な製品にはなりません。作業件数ではなく「使える状態になった機能」「実際に確認できた品質」を見ましょう。

08 / COMMON MISTAKES

よくある5つの間違い

名前を知っているだけでは、開発が上達するとは限りません。

1. 先に完璧な設計を作ろうとする

不確実な部分は、小さく試してから設計を詳しくする方法もあります。

2. アジャイルなら計画不要と思う

変化に対応するためにも、目標と優先順位は必要です。

3. AIの「成功しました」を鵜呑みにする

報告・テスト・最終的な使用結果は別々に考えます。

4. 複数AIを動かせば必ず速いと思う

並列化は、統合や競合が少ない場合に効果が高くなります。

5. すべての工程を同じ方法にする

未知の技術にはPoC、UI改善には反復、固定仕様には計画先行など。

10 / CHECK

自分の言葉で説明できる？

一問ずつ、考えてから答えを開いてみましょう。

Q1：新しく保存機能を追加した。IterativeとIncrementalのどちら？

Incremental。使える機能が増えたから。品質改善が中心ならIterative。

Q2：髪の動きが不自然なので同じ区間で比較して直した。どちら？

Iterative。同じ機能の品質を繰り返し改善している。

Q3：Androidで画面オフ録音が可能か分からない。最初に何をする？

PoC。いきなり全部作らず、実現できるか小さな技術実験をする。

Q4：AIがコードを直したと言った。何を確認する？

実際の成果物と必要なテスト。報告だけでは、期待どおり動くことの証明にならない。
